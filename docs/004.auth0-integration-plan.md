# Notes9 Auth0 Integration Plan

> **Objective**: Integrate Auth0 as the OAuth provider for notes9 using the existing OIDC infrastructure, maintaining all functionality while providing secure, professional authentication.

## 🎯 **Why This Approach Works**

✅ **Uses existing OIDC provider** - AFFiNE already has `providers.oidc` built-in  
✅ **No major code changes** - just configuration updates  
✅ **Professional auth provider** - Auth0 is enterprise-grade  
✅ **Perfect for AWS deployment** - scales seamlessly  
✅ **Maintains air-gap security** - your Auth0 is separate from AFFiNE cloud

## 🏗️ **Current Infrastructure (Already Built)**

Your codebase already has everything needed:

```typescript
// ✅ OIDC provider exists
packages/backend/server/src/plugins/oauth/providers/oidc.ts

// ✅ Configuration schema ready
```

## 🚀 **5-Step Integration Plan**

### **Step 1: Auth0 Account Setup** ⏱️ _5 minutes_

1. **Create Auth0 Account**

   - Go to https://auth0.com
   - Sign up for free account
   - Create new tenant (e.g., `notes9-research`)

2. **Create Application**

   - Application Type: **Single Page Application**
   - Name: `Notes9 Research Platform`
   - Allowed Callback URLs: `http://localhost:3010/api/oauth/callback`
   - Allowed Logout URLs: `http://localhost:3010`
   - Allowed Web Origins: `http://localhost:3010`

3. **Get Credentials**
   - Note down: `Client ID`, `Client Secret`, `Domain`
   - Domain will be like: `notes9-research.us.auth0.com`

### **Step 2: Backend Configuration** ⏱️ _2 minutes_

Update your environment variables:

```bash
# Add to .env.local
OAUTH_OIDC_CLIENT_ID="your-auth0-client-id"
OAUTH_OIDC_CLIENT_SECRET="your-auth0-client-secret"
OAUTH_OIDC_ISSUER="https://notes9-research.us.auth0.com/"

# Optional: Customize claims
OAUTH_OIDC_SCOPE="openid profile email"
OAUTH_OIDC_CLAIM_ID="sub"
OAUTH_OIDC_CLAIM_EMAIL="email"
OAUTH_OIDC_CLAIM_NAME="name"
```

### **Step 3: Frontend Configuration** ⏱️ _1 minute_

Update your server constants to enable OIDC:

```typescript
// packages/frontend/core/src/modules/cloud/constant.ts
export const BUILD_IN_SERVERS = [
  {
    id: 'local-server',
    baseUrl: 'http://localhost:3010',
    config: {
      serverName: 'Notes9 Research Platform',
      features: [ServerFeature.LocalWorkspace],
      oauthProviders: ['oidc'], // 🔄 Change from [] to ['oidc']
      type: ServerDeploymentType.Selfhosted,
      credentialsRequirement: {
        password: { minLength: 8, maxLength: 32 },
      },
    },
  },
];
```

### **Step 4: Docker Environment** ⏱️ _1 minute_

Add Auth0 config to your Docker Compose:

```yaml
# docker-compose.local.yml - Add to backend service environment
services:
  backend:
    environment:
      - OAUTH_OIDC_CLIENT_ID=${OAUTH_OIDC_CLIENT_ID}
      - OAUTH_OIDC_CLIENT_SECRET=${OAUTH_OIDC_CLIENT_SECRET}
      - OAUTH_OIDC_ISSUER=${OAUTH_OIDC_ISSUER}
      # ... your existing variables
```

### **Step 5: Testing** ⏱️ _2 minutes_

1. **Start Services**

   ```bash
   docker-compose -f docker-compose.local.yml up -d
   yarn build && yarn start
   ```

2. **Test Login Flow**
   - Go to `http://localhost:3010`
   - Click login → Should see "Continue with OIDC" button
   - Click it → Redirects to Auth0
   - Login → Redirects back to your app ✅

## 🐛 **Troubleshooting**

### **"OIDC provider not configured"**

- Check environment variables are loaded
- Verify `OAUTH_OIDC_CLIENT_ID` is set

### **"Invalid redirect URI"**

- Verify Auth0 callback URL matches: `http://localhost:3010/api/oauth/callback`
- Check frontend `baseUrl` matches backend

### **"Claims not mapping"**

- Verify Auth0 user profile has `email` and `name`
- Check OIDC claim mapping in environment
